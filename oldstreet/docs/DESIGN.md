# 老街建筑全栈观察站 — 原创设计说明

> 一个把「建筑」与其「门牌号、属性年代、边界、照片、修缮、可进入性」分离建模的历史街区观察系统。
> 本文说明为什么这样建模、关键约束如何落地，以及历史检索与地理分块如何共享同一份一致快照。

## 1. 设计出发点：四个常见错误

在历史建筑信息化里，最容易犯、也最难回收的四个错误：

1. **把门牌号当成建筑身份。** 街道更名、重编、分户之后，同一座建筑得到新号，系统里却多出一座「新楼」，或者旧号的历史直接丢失。
2. **把合院当成不可分割的一。** 一旦析产分户，多个真实使用单元共用一个旧身份，权属、修缮、照片全都无法各自追踪。
3. **把最权威的一条记载当成唯一事实。** 1948 清册、三普、口述、铭牌给出的年代彼此矛盾时，覆盖式更新让「证据差异」永久消失。
4. **把一张老照片自动认成某一立面、把一个关闭的院门当成整条街关闭。** 前者制造虚假的同一性，后者制造虚假的不可访问性。

本站的全部结构都围绕「**身份稳定、事实可溯、对应存疑、开放按点按时**」四句话展开。

## 2. 核心模型（稳定实体 + 时段化附属事实）

```
BuildingEntity (稳定身份，id 不变；可带 validFrom/validTo 表示身份存续期)
 ├── Alias 门牌号  *validFrom ─ validTo*   ← 编号是「时段别名」，不是实体
 ├── Claim 属性陈述 attr/value + sourceId  ← 年代/风格/状态；多来源并存、可撤回
 ├── Event 修缮/改建/拆分事件（日期 + 来源）
 ├── Footprint 空间边界（ring/point + sourceId + kind）
 │     └ supersedes：纠偏时新边界替代旧边界，旧边界撤回但保留
 ├── Photo（拍摄朝向 bearing、估计机位、机位不确定度）
 │     └ PhotoMatch 候选立面对应（pending/confirmed/rejected，置信度）
 ├── Entrance 入口
 │     └ EntrancePeriod 开放时段（state + 每日时刻 + 生效区间）
 └── Relation 谱系：split / merge（from → children）

Source 来源登记簿：authority 0–100，决定属性取舍但不删除异说
```

### 2.1 门牌变更为何「不新建另一座建筑」
门牌是 `Alias(entityId, number, validFrom, validTo, sourceId)`。一次重编号只是
**把旧别名封口（close）+ 新别名指向同一 entityId**。实体的创建时间、事件、照片、边界
全部天然连续。查询「1948 年的槐安街 18 号」与「今天的槐安街 12 号」命中等同一个 E-001。

### 2.2 合院拆分为何「不能沿用单一身份」
拆分（`splitCourtyard`）做三件事：
- 父实体身份止于拆分日（`validTo`），但记录保留，历史日期仍可查询；
- 子女各自获得**新的稳定实体 id**，即使其中一支「沿用主门牌」，也不继承父实体的 id 或事件；
- 写入 `Relation(kind=split, from, children, date)` 与一条 `Event(kind=split)`，谱系可双向追溯。

「沿用门牌」只是子女的一条别名，**门牌相同不等于身份相同**。

## 3. 双时间（Bitemporal）：一致快照的基础

每条事实有两个时间轴：

- **有效时间（valid time）**：事实在现实世界生效的区间 `[validFrom, validTo)`（半开）；
- **事务时间（transaction time）**：系统记录与撤回的时刻 `recordedAt / withdrawnAt`。

读取统一带两个参数：`asOf`（想看哪一天的世界）与 `snapshotAt`（想看系统在哪一刻掌握的版本）。

```
validAt(rec, asOf)      = validFrom <= asOf < validTo
aliveAt(rec, snapshot)  = recordedAt <= snapshot < withdrawnAt
```

由此得到三条关键性质：

1. **历史检索**：asOf=1948 时返回当年门牌、当年状态（E-001 的 weathered/restored 随修缮日切换）。
2. **时间旅行**：撤回一座误录建筑后，用旧 `snapshotAt` 仍能逐字复现撤回前的分页；
   新快照里该建筑收缩消失——「分页中途撤回」不会让页出现空洞或幽灵记录。
3. **纠偏可溯**：坐标新边界 `supersedes` 旧边界，旧点 `withdrawnAt` 落档；新快照展示新点，
   证据面板仍列出旧点及其来源。

> 实现注意：查询过滤器**只**用 `aliveAt`，不能再叠加 `!rec.withdrawn` 布尔硬过滤，
> 否则撤回时刻之前的历史快照会被错误清空（本仓库在测试中专门捕获并回归了这一点）。

## 4. 证据差异：不覆盖异说

`Claim` 是「某来源在某时刻说某属性=某值」的陈述。解析器：

1. 取该实体该属性在快照内的全部陈述（冲突全部保留）；
2. 按 `Source.authority` 降序、`recordedAt` 降序选出采纳值；
3. 返回 `selected` 与 `candidates[]`，并标记 `conflicting`。

页面据此渲染：采纳值给绿框，其他异说给备选框，顶部给出「多来源不一致」警示条。
典型案例 E-005 望江茶园：年代有 1899 / 1908 / 1933 三说（《塔志》、铭牌、三普），
风格有骑楼 / 石库门两说；系统选 1933（S3 权威性 70），但 1899、1908 原样可查。
新增一条权威性更高的实测陈述会立即改变采纳值；撤回该陈述后采纳值自动恢复。

## 5. 空间库：边界、来源与纠偏

- `Footprint.ring` 为 GeoJSON 坐标环，`point` 为代表点，`kind ∈ reported | surveyed | surveyed-corrected`。
- 现行边界选择顺序：纠偏实测 > 实测 > 传闻/清册，同级取登记时间最新。
- 纠偏通过新增记录 + `supersedes` 完成；被替代记录 `withdrawn=true` 但仍出现在详情「空间证据」表。
- 案例 E-005：1948 清册点相对实测向东南偏移约 72 米，2024 实测纠偏；地图上旧点画红色虚线圈叉，新点画实体边界。

**地理分块查询**：按固定经纬度步长 `CHUNK_DEG=0.002`（约 200 m 量级）对代表点做
`floor(lon/deg), floor(lat/deg)` 分桶，返回每块的实体集合与 bbox。分块与列表
**调用同一个 `listBuildings` 快照函数、同一组筛选参数**，从根上保证两个视图的实体集合一致。

## 6. 历史照片：候选对应，而非自动认定

照片携带 `bearingDegrees`（拍摄朝向，0=北顺时针）、`estimatedLocation`（机位）、
`locationUncertaintyM`（不确定半径）。历史照片的机位与视角天然有误差，因此：

- 照片与立面之间用 `PhotoMatch(photoId, entityId, facade, confidence, status)` 关联；
- 任何新候选一律 `pending`，系统**永不自动置 confirmed**；
- 同一照片可有多个立面候选（P-001 有正立面 0.62 / 山墙 0.34 两案并存）；
- 只有人工 `decide` 才能确认/否定，并记录决定人与理由；
- 照片文件缺失（如 P-003 文件 404）不删除元数据与候选，前端显示「文件缺失」占位。

地图上用三角箭头表示机位与朝向，高不确定度画误差圈。

## 7. 开放状态：入口 × 时间，拒绝以偏概全

- 街区有自己的入口（街门）；建筑可有独立入口。每个入口有多条 `EntrancePeriod`
  （state=open/closed/restricted + 周一至周日时刻表 + 生效区间）。
- 判定一个入口在 `day/time`：先选当日生效时段（重叠时取最近开始者），再按
  **UTC 正午取星期**（避免本地时区把日期推到前后一天）比对当日营业时刻：
  `open / outside-hours / restricted / restricted-closed / closed / unknown`。
- **整街是否可进入 = 是否至少一个街门为 open**。东街门 2026-09-29 起检修关闭，
  西街门仍开放，因此街区 `siteOpen=true`；E-003 院门检修关闭只影响该院。
- E-008 糖仓为 `restricted`（周一闭园、其余时段需预约），与一般开放严格区分。

## 8. 双索引比较：现门牌 vs 稳定实体 + 时段别名

`/api/compare/indexes?asOf=...` 并排计算两种策略：

| 策略 | 做法 | 1948 历史检索 |
|---|---|---|
| A 时段别名 | 取 asOf 当日 `[from,to)` 生效的别名 | E-001→槐安街18号 ✓ |
| B 仅现门牌 | 只认 `validTo=null` 的门牌，历史靠名称回退 | E-001 无门牌号，只能模糊搜名，**漏检** |

结论以表格呈现：在 1948-06-01 快照下 B 对 E-001/E-002/E-005 等全部漏检，
A 全命中。系统的列表、详情、地图统一采用 A；该接口把设计权衡显式暴露给使用者与测试。

## 9. 一致快照如何贯穿列表分页与地图

- 列表为**不透明游标分页**：游标 `base64url({k: sortKey, id})`，排序键为门牌数字 + 实体 id
  （稳定、与时间无关）；`asOf/snapshotAt/筛选` 在翻页过程中保持不变，快照被「钉住」。
- 撤回发生在分页中途时：旧游标 + 旧 snapshot 仍遍历旧集合；新 snapshot 下 total 收缩、后续页自动补齐，无重无漏。
- 地图分块复用同一快照函数，故「键盘操作的列表」与「地图上的边界/点位」永远是同一批实体。

## 10. 前端与可访问性

- 零第三方前端依赖：地图为**原创 Canvas 渲染器**（拖拽、以光标为中心缩放、网格、分块框、
  边界、纠偏旧点、带朝向的照片机位、街门状态）。
- 键盘：列表 `↑/↓` 选择、`Enter` 详情、`←/→` 或 `PageUp/PageDown` 翻页、数字键直选；
  地图方向键平移、`+/-` 缩放、`Enter` 选中悬停实体。列表与地图共享同一筛选状态。
- 详情面板分区：谱系 → 门牌沿革 → 证据差异 → 空间/纠偏 → 修缮事件 → 照片候选 → 入口开放。

## 11. 后台与审计

后台写接口需 `X-Admin-Token`；所有变更（实体、别名、renumber、split、陈述、撤回、
事件、边界、照片、候选裁定、入口时段）写 `audits`（时间、操作人、动作、对象、前后细节）。
**撤回是软操作**：不物理删除，保留事务时间证据。

## 12. 技术取舍

- 零外部 npm 依赖：Node 内置 `http` + JSON 文档库 + `node:test`，离线可跑、易审计；
  空间查询用固定网格（街区尺度足够），未引入 PostGIS 等外部组件；
- JSON 存储按事务落盘，仓储接口（`repo.js`）与存储无关，可平滑替换为关系库 + 时空索引；
- 受控词表（年代桶 / 风格 / 保存状态）集中于 `db.js`，筛选与展示共用同一来源。
